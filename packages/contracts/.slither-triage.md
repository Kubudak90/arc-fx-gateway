# Slither finding triage

Per Plan 7. Slither runs in CI with `fail-on: medium`. Findings rated medium or higher must either be fixed in code or documented here with a reason. New findings without an entry will fail CI.

Update process:

1. Run `slither packages/contracts --filter-paths 'lib/|test/'` locally.
2. For each finding rated medium+ that we accept, add a row below with: file:line, detector, severity, reason, and the date you reviewed.
3. If a finding's reasoning becomes stale (e.g. surrounding code changed), re-evaluate and either fix or update the row.

Audit scope is `ArcFXGatewayV10.sol` and the libraries it imports. V10 is the current canonical deployment (v1.0, 2026-05-06) with per-invoice escrow custody. V8 and V9 are retired — sources moved to `legacy/src/`, tests to `test/legacy/`; both are out of scope. Deprecated contracts (`ArcFXGateway.sol` v0.6/v0.7, `pool/*`, `registry/*`, `OracleAMM.sol`, `PriceGuard.sol`) are in `legacy/` and also out of scope. Updated Task 15 (2026-05-06).

> **Note:** V8/V9 sources live in `packages/contracts/legacy/src/`; their tests in `packages/contracts/test/legacy/`. Run `forge test --profile legacy` to execute the legacy suite. They are excluded from the default Foundry profile and from CI coverage.
